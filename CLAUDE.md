# Starfall Meadow (GBA) — notes for Claude Code

Starfall Meadow is a Tamagotchi-style Game Boy Advance game, formerly "Critter Keep". Since port stage 5 (Nov 12 2026)
it is built entirely from our own sources. Those are `ext.c` (our game) plus the original Critter Keep, now in C
(`orig.c` by hand, `orig_update.c`, `orig_render.c` and `orig_main.c` lifted, and `start.s` for startup), with the
original's data generated by `gen/orig_data.py`. `CritterKeep_original.gba` stays in the repo only as the reference
for the port tools. The current release is **v8.3**
(Nov 14, 2026; `StarfallMeadow_v8.3.gba`). See `README.txt` for the feature history and `MANUAL.md` for the player's manual.

## Working agreement (the owner's standing rules)

- **Ask before each stage.** Propose a plan and wait for approval before building. For anything visual (sprites,
  layouts, new screens), show a **mockup first** (a PNG sheet) and build only after approval.
- **Don't change balance, prices or stats on your own.** Ask first, even for a small tweak. For example, milk
  stays at 10 coins although it now does the same as the apple (8).
- **Ship a test ROM after each stage** (`StarfallMeadow_v8.Nx_test.gba`) with in-game screenshots of what changed.
- **Keep the stat budget:** at most about 8 to 10 things may raise each stat (happiness, hunger, health; bond is gone).
  New features should reward collection or cosmetics rather than add stat boosts.
- **Every decor piece stays in the game** with its animation and message, even when it has no stat effect.

## Build

Toolchain: `clang` (armv4t target), `ld.lld` and `llvm-objcopy` (`llvm-objdump` is used by
`mkrom.py`), and Python 3 with Pillow (for the art generators and tests).

```
./build.sh            # -> CritterKeep.gba (the playable ROM) and ./emu (the test emulator)
```

Repo layout: the ROM sources (`ext.c`, `orig*.c`, `start.s`, `header.inc`, `*.h`, `link.ld`, `mkrom.py`, `build.sh`) sit
in the root; the art/music generators live in `gen/` (with `gen/bg/` and `gen/picture_src.jpg`).
All paths are relative to the repo (no more `/home/claude/...`). Generators that write headers find the root from
their own location; `bgfx.py` and `tunes.py` write `../*.h`, so run them from inside `gen/`; `picture.py` runs from
the root. Build outputs (`ext.o/.elf/.bin`, `CritterKeep.gba`, `emu`) are git-ignored; the release ROM is committed
as `StarfallMeadow_v<N>.gba`. The layout (`link.ld`) has the header and startup at `0x08000000`, then the entry stubs
`ext.c`'s `O_*` constants point at (the original's addresses), then the original's data at its own address
(`0x0800FB1A`), the port at `0x08012000`, `ext.c` at `0x08020000`, and the lifted `game_render` after `ext.c`'s data.

**No writable globals:** the extension runs from ROM. Any `static` or global variable that isn't `const` makes
the build fail with "BUILD FAILED: no globals allowed" (`mkrom.py` reports a writable section). All state lives
in `struct State` (the macro `G`, at `0x0203E000`). Add new fields at the end of `State`. It is about 2 KB; nothing else
in the extension uses the RAM just after it, but check the size if you add a lot.

## Tests

The test emulator: `./emu` (built by `build.sh`). Usage: `emu rom.gba script [sram]`. It writes SRAM back
to the save file, so always copy a save first (the tests do this).

`python3 tests/run_tests.py <sections...>`. There are 228 checks (as of v8.3).
Run them in batches, each taking up to about 10 minutes:

1. `fidelity`: since v8.3, the care pace (seconds per hunger and happy heart); the old v7 clock match is retired
2. `growth secrets care save fast rebal`
3. `games fixes unlocks journal b1 stories health`
4. `garden budget fuzz`
5. `fly sprites yard`

Other details:
- `CUR_VER = 15` is the save version. `BASE14 = tests/baseline_v81b2.gba` is a save-version-14 build used for
  the save conversion test.
- `budget` checks that busy screens stay under about 280,000 CPU cycles a frame. Text costs about 2k cycles per
  character, so cache static text in `SCRATCH_BG` and copy it each frame (see `garden_words` and `fly_words`).
- The struct offsets used in pokes come from parsing `ext.c`, via `g('field')` and the `OFF` map in
  `run_tests.py`. Add new fields to that map.
- `tests/shots.py` is a screenshot helper. The script command `shot file.ppm` also works (the emulator's script
  arguments are cut at 63 characters, so use short or relative paths).
- The test emulator does **not** draw hardware sprites (OBJ), windows or alpha blending. For screenshots of those, use
  the real mGBA core: `apt-get install libmgba-dev`, then
  `cc -O2 tools/mgba_shot.c -o mgba_shot -lmgba` and `./mgba_shot rom.gba script.txt save.sav` (the same script
  commands: `wait`, `waitscene`, `press`, `poke8`, `poke32`, `peek`, `shot`). The `sprites` tests check OAM and the registers.

## Code map (`ext.c`, about 4,700 lines)

- **Modes** (`G.mode`): `M_NONE, M_MENU (START), M_EXTRAS (SELECT), M_SENDOFF, M_SHOP, M_BAG, M_EAT, M_MINI,
  M_ALBUM, M_SURE, M_DEX (journal), M_NAME, M_STORY, M_GARDEN, M_FLY`.
- **Entry points:**
  - `hook_update`: the per-mode update switch.
  - `hook_render`: the per-mode draw.
  - `hook_bg_copy`: draws the room or yard background with sky and decor animations, plus the firefly lantern.
- **Core:**
  - `sim_tick` runs every 60 frames (24 on FAST; v8.3, was 90/36), and handles needs, health and the clock.
  - `life_watch` handles mornings, cries and the bed's happy morning.
  - `decor_tick` handles decor use (messages and kind boosts; no happiness since v8.1).
- **Original game addresses:** `PET` at `0x03000028` (the health is `P16(0x16)`, 0–100), `SCENE` at
  `0x03000020`, `MSG_BUF` at `0x030002A4`, `MSG_TIMER` at `0x0300001C`, `FRAMES` at `0x03000018` and the clock
  `PET_CLOCK` at `0x0300004C`.
- **Time:**
  - A day is 600 clock steps; night is steps 480–599. A tick is 1 s (v8.3).
  - By day the clock moves a step every tick (8 minutes); at night 2 steps every 3 ticks (3 minutes): an 11-minute
    day. The critter's own counters count every tick, and every care timer in `sim_tick` counts 1.5x the ticks it
    did before v8.3, so care keeps the same real-time pace (the `fidelity` checks). PET's cooldown (`P16(0x40)`, set
    when petting raises happiness) is set to 90 in the original's own code (`orig_update.c`, was 60) and counts down
    every tick: 90 s.
  - The clock runs in `M_NONE`, `M_EXTRAS`, `M_NAME`, `M_GARDEN` and `M_FLY`. It is paused everywhere else.
- **Display:**
  - The game uses Mode 4 (8-bit bitmap) with page flipping. Draw through `DRAW_TARGET`.
  - `pset` is a read-modify-write of 16 bits, so it is slow.
  - `YARD_BG` holds the pre-rendered room or yard (from `build_bg`), and `SCRATCH_BG` is the cache for static
    text and bars.
- **Palette map:**
  - `0–39`: the `C_*` UI colours. With the lights off at night the original dims these: `C_GOLD` and `C_GREEN`
    go dark; `C_LTEXT`, `C_LILAC` and `C_ORANGE` stay readable.
  - `40–63`: reset by the original every frame, and borrowed by food (`M_EAT`), stories and the garden.
  - `120–143`: the critter.
  - `144–207`: room and yard colours (`BGX`). v8.3: the room uses only the first 52 (`BGX_ROOM_N`, 144–195), so
    indoors 196–207 are free for a fifth decor band; the yard keeps all 64.
  - `208–243`: the decor bands.
  - `244–254`: the garden. `garden_palette_on()` decides when it's loaded.
  - `255`: the ember firefly. In the room, `244–255` are the ceiling decor piece's band (v8.3: they used to be
    overwritten with the firefly colours, so ceiling pieces showed in the wrong colours; `fly_palette` is gone).
- **Save:** magic `CKS8`, version 15, 11 parts (part 10 is the Garden). `More.spare` is used as follows:
  - `[0]`: the night of the last wish (day+1)
  - `[1]`: the night of the last story
  - `[2]`: a story read tonight, for the morning (v8.3: no bond any more)
  - `[3]`: the firefly kinds found (bits)
  - `[4]`: fireflies caught in all
  - `[5]`: the best night
  - `[6]`: tonight's marker (day+1)
  - `[7]`: rounds used tonight (bits 0–1), plus tonight's kinds shifted left by 4
  - v8.2b: `More.pad0` is the other place's mess (see the yard mess below), and `More.pad1` bit 0 = saved and quit
    in the yard, bit 1 = the mess counts are swapped (outside). Saves always store them unswapped.
- **Generators → headers:** (also `sprfx.py` → `sprfx.h`, the sprite tiles)
  - `bgfx.py` → `bgfx.h` (the room and yard pictures, including the tree trunk)
  - `garden_art.py` + `gardengen.py` → `garden.h`
  - `critters.py`, `newforms.py`, `limbs.py` and `critgen.py` → `critters.h`
  - `decor.py` / `decorgen.py` → `decor.h`
  - `icons.py` / `icongen.py` → `icons.h`
  - `baricons.py` → `baricons.h`
  - `title.py` → `title.h`
  - `minis.py` → `minis.h`
  - `tunes.py` → `tunes.h`
  - `picture.py` → `picture.h`
  - `foodart.py` → `foodart.h`

## v8.1 design decisions (already approved and built)

- **Yard:** the three moonflower patches sit at the "B5c" spots: `PATCH_X = {80,132,152}`,
  `PATCH_Y = {110,104,127}`. They are drawn before (behind) the decor, and the critter stands in front of them.
  The garden opens in look mode: A tends (the cursor shows), B puts the cursor away, and B again goes inside.
  SELECT over the night yard opens a menu with only GO INSIDE and JOURNAL (v8.3: plus CLEAN UP when needed).
- **Fireflies:**
  - R in the night yard starts a 30 s round, with 3 rounds a night.
  - There are 12 kinds: 3 common, 2 of 5 uncommon each night, and 4 rare. Moonglow needs a full moon, Rose Heart
    a rose in bloom, Wish Spark a wish made that night, and Starfly about 1 night in 10 with 2+ blooms.
  - Rare kinds are decided at nightfall, so extra rounds can't farm them.
  - Catching gives no coins and no stats.
  - The night's catch shows as a lantern (v8.3: on its stand by the bed), and it is released at dawn.
  - Once all 12 are found, they dance at the window every night.
- **Shooting stars:** about 1 night in 3, one star at a random step of the night. The message reads
  "A SHOOTING STAR! A: MAKE A WISH", and A still works for about 3 s after the star has crossed.
- **Stories:** one a night. (v8.3v: switched off, `STORIES_ON` 0 in ext.c; the code stays for later use.)
- **Journal:** in the SELECT menu, not START. The tab strip scrolls (`jt_first`), and there is a FIREFLIES tab.
- **Minigames:**
  - A 50% checkerboard fade over the room or yard during a round (drawn once in `prerender_mini`).
  - The big words are outlined (`textbig_o`), with two offset copies to stay inside the frame budget.
  - Yard games load the garden palette.
- **Rebalance:**
  - Decor no longer raises happiness; the bed keeps its +1 each morning.
  - Milk gives hunger only, and soap only cleans.
  - The mobile, plane, portrait and clock are kind `DECOR` (`KD`), with no care boost; the portrait keeps its
    bond.
  - A happy rise no longer counts as a play point by itself. That fixed a bias where idle play decor pushed every
    critter toward Fluffbud.
- **Fixes:** no name on the status card before naming, and a darker tree trunk with no green stripe.

## v8.2: hardware sprites (released in v8.2)

- **How sprites work here:** the game is a Mode 4 bitmap, and the original never used OBJs. `hook_render` calls
  `spr_begin()` and the draws fill a shadow in `State` (`so`, `sa`, `sp`, `spr_*`, `win`). The next `hook_update`
  calls `spr_sync()` right after `fx_watch()`, and it sets or clears OBJ (0x1000), 1D mapping (0x40) and WIN0
  (0x2000) in `DISPCNT`. (Since the port, `main`'s page flip in `orig_main.c` keeps those three bits. Before, it
  rewrote `DISPCNT` every frame and `spr_sync` had to OR them back in each time.) Tiles (`gen/sprfx.py` -> `sprfx.h`, 38 tiles) load to
  0x06014000 (tile 512) when sprites switch on; the OBJ palette (0x05000200) is free for us.
- **Blending:** every sprite is semi-transparent and blended additively (`BLDALPHA` 16/16, BG2 and the backdrop as
  second targets, ORed into `BLDCNT` after `fx_tick`). A sprite fades by darkening its own palette bank. OBJs are
  never a brightness target, so the farewell's white-out leaves them sharp (the star's rays switch to solid,
  pre-whitened colours while the picture is mostly white, and its halo hides).
- **Firefly release:** at dawn the window swings open (`win_open_pre/post`: the middle bars give way to sky and the
  two panes are drawn edge-on), the cork pops at frame 40 and each firefly is a heart (8x8) plus an affine glow
  (16x16) that shrinks and fades as it flies out; WIN0 limits the sprites to the open window. Then the window shuts.
  The release is only drawn in the room with no menu open.
- **Farewell star (the shared rise only; the five original secret-form farewells are unchanged):**
  `star_sprites()` - a halo (32x32, double-size affine) and turning rays. The light gathers on the critter as it
  rises, glides to (120,58) in the sky, then breathes and turns. Wonderful/happy/sad set its size; sad is faint.
- **Avoid software divides** in per-frame code: `/` by a variable costs a few hundred cycles on the GBA
  (`__aeabi_idiv`). A per-pixel divide in the first window-pane line drawer cost about 60k cycles a frame.

## v8.2b: fixes and changes (released in v8.2)

- **Yard mess:** `PET[P_POOP]` is always the room's mess and `More.pad0` always the yard's (since the port; before,
  they were swapped while outside). `MESS_HERE` (`ext_mess_here()`) is the one where the critter is: the original's
  CLEAN and its mess checks in `orig_update.c` use it, and so do pooping (`sim_tick`), soap and the care record. The
  original's room-poop drawing in `orig_render.c` reads `ext_mess_drawn()`, which is 0 outside. Both messes count
  toward getting sick (`mess` in `sim_tick`; since v8.3 the yard's only while it's awake). Note: to make it poop in a test, push the poop timer
  (`P16(0x2C)`/`P16(0x2E)`), as the `yard` test does.
- **Moonflower colours:** `garden_palette_on()` is true on every screen over the yard (menus, bag, feeding,
  petting). Outside, the food art uses the wall picture's slots 96–119 (`food_base()`), which the room only needs.
- **Save and quit in the yard** sets `More.pad1` bit 0; CONTINUE goes back outside (if awake, well and lights on).
- **LIGHTS outside:** caught before the original sees it (the icon cursor is `ICON_CUR`, 0x030002D8; 1 = LIGHTS).
- **Toys:** the pinwheel, sprinkler and resting frisbee share `TOY_X` = 108, between the first two moonflower
  patches, clear of every yard decor piece (by the tree: up to x 88; by the house: from x 168).
- **Jar:** a soft breathing glow sprite (`jar_glow`) instead of specks round it.
- **Garden:** planting leaves the soil dry; A again brings the watering can (`gen/can.py` -> `can.h`, garden
  palette; it pours only from its rose; keys wait `CAN_T` frames); watered soil is drawn dark (`soil_wet`).
  Rare odds: moon lily 1/3, starbloom 1/2, twinglow 1/5, aurora 1/20. Journal flowers stand on their soil.
- **Fireflies:** 20 s rounds, the jar moves 3 px a frame, a faint glow counts (catch area unchanged). The totals
  (caught, best night) moved from the firefly page to the RECORDS tab.
- **Length:** `LIFESPAN` 8 grown-up days (was 12); `shop_level()` opens a level every 2 grown-up days so all six
  still open. Every secret form needs only its first 2 grown-up days. (Teen, child and day length unchanged.)

## v8.2c (released in v8.2)

- **Journal flowers:** the double-size flower and its stem are placed so the stem ends in the soil (`oy=98-2h`).
- **RECORDS scrolls** (UP/DOWN, `G.jrec`): 10 of `REC_ROWS` rows show, with arrows; add rows in `jr_records`.
- **Yard poops** are ours: `yard_poops()` draws up to four at `YP_X/YP_Y` (front, two middle, back; smaller further
  back; `gen/poop.py` -> `poop.h`). The spots were found by mapping every pixel any decor piece, toy or moonflower can
  cover (plus the house and tree), so nothing ever overlaps. The original draws no poops outside (`ext_mess_drawn()`
  is 0 there). The count to draw is kept in `G.yp_n`.
- **Runaway (health ran out), "a home in the wild":** `runaway_draw` plays six shots (`RA_T1..RA_T5`, timed by
  FRAMES), each fading in from black: its room at dawn (warm palette, empty bowl, bindle), the yard at sunrise (one
  look back at the house), the meadow path (it shrinks 3 -> 2 -> 1 as it walks away), the stream where a wild grown-up
  of its own kind is looking after two little Bliplets by their burrow under the willow (one hops over to say hello;
  it stays and helps take care of them), the night sky where a faint glow (sprite)
  flickers out at its star's place, and the end card ("NOT EVERY CRITTER BECOMES A STAR."). The words sit in the
  bottom bar (`ra_box`) so the picture stays clear. New art: `gen/meadow.py` -> `meadow.h` (two painted 240x106
  backgrounds, one 96-colour palette from 144: `runaway_palette`; the wild grown-up uses the runaway's own art; the
  Bliplets are 256-colour sprites (`spr_bliplet`, `bl_tiles_load`: six poses of `CR_PIX` form 1 at 32 px copied to OBJ
  VRAM from unit `BL_UNIT`, their colours put in the OBJ palette's critter slots) since BG2 has one critter palette).
  Lore: star-seeds sometimes land in the meadow and hatch wild, with nobody to raise them; the grown-ups there are
  kindred spirits who left for the same reasons.

## Porting the original (started Nov 12 2026)

- **Stage 1 is done:** see `port/PORT_MAP.md` (the map of every function, the data and the RAM), `port/orig.lst` (the full
  listing, from `tools/disasm.py`), `gen/orig_data.py` (all the original's data, which rebuilds byte-identical) and
  `tools/lockstep.py` (runs two ROMs on one script and names the first differing RAM bytes or pixels; it uses the
  emulator's `trail` command).
- **Stage 2 is done:** every helper now runs from `orig.c` (linked at `0x08012000`, before `ext.c`, which doesn't move).
  Until stage 5, `patch.py` redirected the original's call sites and put a jump at each ported entry. Check a
  port with `python3 tools/port_check.py REF.gba`, where REF is a build from before the change: it must say ALL
  IDENTICAL. See `port/PORT_MAP.md`.
- **Stages 3 and 4 are done (lifted):** `game_update` and `game_render` run from `orig_update.c` and `orig_render.c`,
  generated by `tools/lift.py` (an exact instruction-by-instruction translation to C). The lifted files are now the
  source. Don't hand-edit them: to change what a part does, rewrite that part as readable C and check it with
  `port_check` against the build from before. (Re-lifting needs the last patched build as `LIFT_ROM`, which is no
  longer made.)
- **Stage 5 is done:** the build is standalone. `start.s` has the header (`header.inc`), the startup and interrupt
  handler, the 9 entry stubs and the original's data (`.incbin` of `orig_data.bin`). `main` is lifted
  (`orig_main.c`), and `mkrom.py` replaces `patch.py`. Each switch's table is copied into the lifted C, since the
  original kept it in its code area, which is now empty.
- **Workarounds retired (Nov 12 2026):** the original's own code was changed in place:
  - PET's cooldown is set to 90;
  - the weight line says "LB";
  - `main` keeps the sprite bits;
  - the mess goes through `ext_mess_here()`/`ext_mess_drawn()`.

  Each edit in a lifted file is marked `EDITED` and was checked screen for screen against the build before.
  The lifted files are ordinary source now: change them where needed, keeping each change small and marked.
- **Port rules learned:** a call the original made at a site `patch.py` hooked still goes through that hook. For
  example, every `draw_sprite` call in the original goes to `ext.c`'s `hook_sprite` (also `hook_room_critter` and
  `hook_bg_copy`), so ported code calls `hook_sprite`, not `o_draw_sprite`. The lifted code already does.
  Write VRAM 16 bits at a time (`volatile u16`), since a byte store writes both pixels. Check
  odd library routines against the original with `tools/orig_call.py` (needs `pip install unicorn`). New `orig.c` data
  goes to `.rodata`, which is fine; writable globals are still not allowed.
